# عالم عبودين — Aboden Fun World

Arabic RTL, mobile-first project directory. **Interface preview only: no repositories have been approved or added.**

## Scope and approval

Each project requires the owner's explicit approval before entering either `src/data/catalog.json` or the published site. Design approval does not approve repositories. There is no runtime GitHub import, API token, analytics, fake project imagery, or invented usage data. See `AGENTS.md`.

The approval ledger `src/data/approvals.json` and catalog are empty. The build fails if a catalog entry lacks an exact matching approval record. Unapproved data must never be saved in browser assets or in the published HTML.

## Development

Requires Node >=22.12.0 (CI uses Node 24).

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

`astro.config.mjs` includes `/Aboden-fun` as the base path. Always preserve that prefix in internal links and assets. The site is statically generated by Astro; the reusable TypeScript renderer produces its HTML without shipping a frontend framework. Local device fonts are used; no font files are distributed.

An offline visual preview requires no npm dependencies:

```sh
npm run preview:offline
python3 -m http.server 4173 --directory .preview
# Open http://localhost:4173/Aboden-fun/
```

It uses the same renderer and public assets as the Astro routes, but is not a substitute for a passing Astro build.

## Structure

- `src/templates/`: shared semantic HTML layout and homepage.
- `src/lib/catalog.ts`: typed project schema and fail-closed approval validation.
- `src/lib/site.ts`: escaped, static HTML renderer; only approved project pages are generated.
- `src/pages/`: Astro routes, including project details, licenses and 404.
- `public/site.css`: responsive design, focus states and reduced-motion support.
- `public/app.js`: local Arabic/English search, filtering, sorting and accessible mobile menu.
- `tests/`: approval, security, routes and search normalization tests.

## Publishing

The verification workflow only builds and stores a preview artifact. **It never deploys.** The initial CI run also stores the resolved `package-lock.json` with the preview; commit that reviewed lockfile and switch installs to `npm ci` before production release.

After explicit design/publication approval, configure repository **Settings → Pages → Source → GitHub Actions**. The separate `Publish approved interface` workflow is manual and requires `PUBLISH`. This controls website publication, not per-project approval. Preview mode intentionally has `noindex, nofollow` and a blocking `robots.txt`; remove these and the preview badge only when the owner approves public indexing.

Do not claim a live URL until a successful Pages deployment has been verified.

## Adding an approved project

First inspect the actual project and ask the owner whether to add that exact repository. After explicit approval: record the repository, approval date and faithful instruction in the ledger; add accurate names, description, category, local genuine image, instructions and verified device list to the catalog. Add a live HTTPS URL only if tested. No play link appears without one. Keep any required source/asset credits with the project and update the licenses page. Then run tests/build and review mobile screenshots.

The site does not move or merge project source, change another repository, or replace game hosting/multiplayer servers.
